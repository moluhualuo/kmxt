## 🎨 完整流程可视化

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                          阶段 1：模型加密与登记                              │
│                         （开发者本地 + KMXT 服务端）                          │
└─────────────────────────────────────────────────────────────────────────────┘

  开发者本地                       HTTPS                    KMXT 服务端
  ┌──────────┐                                           ┌──────────────┐
  │ 明文模型 │                                           │ PostgreSQL / │
  │ .onnx   │                                           │  JSON Store  │
  └─────┬────┘                                           └──────▲───────┘
        │                                                       │
        │ 1. kmxt-cli encrypt-model                            │
        ▼                                                       │
  ┌────────────────────────┐                                   │
  │ 随机生成 32 字节 DEK    │                                   │
  │ + Nonce + Tag          │                                   │
  │ AES-256-GCM 加密       │                                   │
  └───────┬────────────────┘                                   │
          │                                                    │
          ├─► Delta_INT8_192.vmp (密文) ──────┐               │
          │                                   │               │
          └─► contentKey (DEK 明文)           │               │
              cipherSha256                    │               │
              nonce, tag                      │               │
                                              │               │
          2. POST /api/v1/apps/{id}/artifacts │               │
          ────────────────────────────────────┼───────────────┤
          {                                   │               │
            "contentKey": "BASE64URL...",  ◄──┘   ┌───────────▼──────────┐
            "cipherSha256": "3a7f8b...",       │   │ encryptedDek =      │
            "nonce": "...",                    │   │ AES_rootSecret(     │
            "tag": "..."                       │   │   "artifact-dek:id",│
          }                                    │   │   contentKey        │
                                               │   │ )                   │
                                               │   └─────────────────────┘
                                               │
          3. API 返回（⚠️ 不含 contentKey）   │
          ◄──────────────────────────────────┤
          {                                   │
            "id": "ab12cd34-...",             │
            "cipherSha256": "3a7f8b...",      │
            "encryption": {                   │
              "nonce": "...",                 │
              "tag": "..."                    │
            }                                 │
            // ❌ NO contentKey               │
          }                                   │


┌─────────────────────────────────────────────────────────────────────────────┐
│                       阶段 2：APK 打包（构建时）                             │
└─────────────────────────────────────────────────────────────────────────────┘

  开发者本地                                              Android APK
  ┌────────────────────┐                              ┌──────────────────┐
  │ Delta_INT8_192.vmp │ ─────────────────────────────►│ assets/          │
  │   (密文)           │  复制到 src/main/assets      │  *.vmp (密文)    │
  └────────────────────┘                              └──────────────────┘
                                                      ┌──────────────────┐
  build.gradle                                        │ BuildConfig      │
  buildConfigField(                  ────────────────►│  ARTIFACT_ID     │
    "MODEL_DELTA_192_ARTIFACT_ID",                    │  SHA256          │
    "ab12cd34-..."                                    └──────────────────┘
  )                                                   
                                                      ❌ DEK 不在 APK 内


┌─────────────────────────────────────────────────────────────────────────────┐
│                     阶段 3：用户激活卡密（运行时）                            │
└─────────────────────────────────────────────────────────────────────────────┘

  Android 客户端                   HTTPS                   KMXT 服务端
  ┌──────────────┐                                      ┌────────────────┐
  │ 用户输入卡密 │                                      │ 验证卡密有效性 │
  │ KMXT-XXXX... │ ─────► POST /api/v1/sessions ──────► │ + 设备指纹     │
  └──────────────┘                                      └────────┬───────┘
                                                                 │
                  ◄────── 返回会话令牌 + Ed25519 签名 ───────────┘
                         (AES-GCM 加密)
  ┌──────────────────────┐
  │ Android Keystore     │
  │ 加密存储会话令牌      │
  └──────────────────────┘


┌─────────────────────────────────────────────────────────────────────────────┐
│                 阶段 4：请求模型租约（🔥 核心流程）                           │
└─────────────────────────────────────────────────────────────────────────────┘

  Android Native (C++)              HTTPS                  KMXT 服务端
  
  1. 生成临时密钥对
  ┌────────────────────────┐
  │ X25519 私钥 (32 字节)  │ ◄── 仅在内存，不落盘
  │ X25519 公钥 (32 字节)  │
  │ Nonce (16 字节)        │
  └───────────┬────────────┘
              │
              │ 2. 请求租约
              ▼
  POST /api/v1/leases/model-artifacts ─────────────┐
  {                                                │
    "artifactId": "ab12cd34-...",                  │
    "clientPublicKey": "BASE64URL_X25519_PUB",     │
    "requestNonce": "RANDOM_NONCE"                 │
  }                                                │
                                                   │
                   服务端处理                      ▼
                   ┌──────────────────────────────────────┐
                   │ 1. 解密 encryptedDek:               │
                   │    contentKey = AES_rootSecret_dec( │
                   │      "artifact-dek:id",             │
                   │      encryptedDek                   │
                   │    )                                │
                   │                                     │
                   │ 2. 生成临时服务端密钥对              │
                   │    serverPriv, serverPub = X25519() │
                   │                                     │
                   │ 3. ECDH 密钥交换                    │
                   │    sharedSecret = X25519(          │
                   │      serverPriv,                   │
                   │      clientPublicKey               │
                   │    )                               │
                   │                                     │
                   │ 4. HKDF 派生 AES 密钥               │
                   │    aesKey = HKDF_SHA256(           │
                   │      sharedSecret,                 │
                   │      salt: "kmxt-lease-v1",        │
                   │      info: artifactId + nonce      │
                   │    )                               │
                   │                                     │
                   │ 5. AES-256-GCM 加密 DEK            │
                   │    wrappedKey = AES_GCM_enc(       │
                   │      contentKey, aesKey            │
                   │    )                               │
                   │                                     │
                   │ 6. Ed25519 签名整个响应             │
                   └──────────────┬───────────────────────┘
                                  │
  3. 返回加密的租约                │
  ◄───────────────────────────────┘
  {
    "lease": {
      "artifactId": "ab12cd34-...",
      "algorithm": "X25519-HKDF-AES-GCM",
      "wrappedKey": "BASE64URL_ENCRYPTED_DEK",  ◄─ 加密的 DEK
      "ephemeralPublicKey": "BASE64URL...",     ◄─ 服务端临时公钥
      "nonce": "...",
      "tag": "...",
      "expiresAt": "2026-07-24T12:05:00Z"       ◄─ 5 分钟有效期
    },
    "signature": "ED25519_SIGNATURE"
  }

  4. Native 层解包
  ┌────────────────────────────────────────┐
  │ ✅ 验证 Ed25519 签名                   │
  │ ✅ 验证 artifactId / requestNonce      │
  │ ✅ ECDH: shared = X25519(              │
  │      clientPriv, ephemeralPublicKey)   │
  │ ✅ HKDF: aesKey = derive(shared, ...)  │
  │ ✅ AES-GCM: contentKey = decrypt(      │
  │      wrappedKey, aesKey)               │
  │ ✅ 存入临时 handle 表（不暴露给 Java） │
  └────────────┬───────────────────────────┘
               │
               │ 5. 返回 handle ID
               ▼
  Kotlin: val lease = ModelLease(handleId)


┌─────────────────────────────────────────────────────────────────────────────┐
│                   阶段 5：解密模型并推理（最后一步）                          │
└─────────────────────────────────────────────────────────────────────────────┘

  Kotlin                          Native (C++)                推理引擎
  
  1. 读取密文
  ┌─────────────────┐
  │ assets/         │
  │ Delta_192.vmp   │
  └────────┬────────┘
           │
           │ 2. 校验 SHA-256
           ▼
  if (sha256(vmp) != BuildConfig.SHA256)
      throw SecurityException()
           │
           │ 3. 调用 lease.decrypt(vmp)
           ▼
  ┌──────────────────────────────┐
  │ Native handle 表查询          │
  │ handleId -> contentKey        │  ◄── DEK 明文（32 字节）
  │                              │
  │ AES-256-GCM 解密密文:         │
  │ plaintext = decrypt(          │
  │   vmp, contentKey, nonce, tag │
  │ )                            │
  │                              │
  │ 擦除 handle（消费一次）       │
  └──────────┬───────────────────┘
             │
             │ 4. 返回明文模型
             ▼
  ┌────────────────────┐         ┌──────────────────┐
  │ Delta_INT8_192     │ ───────►│ ONNX Runtime /   │
  │   (明文 ONNX)      │         │ ncnn / TFLite    │
  └────────────────────┘         └──────────────────┘
             │
             │ 5. finally { lease.wipe() }
             ▼
  ┌──────────────────────────┐
  │ Native 擦除所有痕迹:      │
  │ - contentKey.fill(0)     │
  │ - X25519 私钥擦除        │
  │ - plaintext.fill(0)      │
  └──────────────────────────┘


┌─────────────────────────────────────────────────────────────────────────────┐
│                         🔐 安全边界总结                                      │
└─────────────────────────────────────────────────────────────────────────────┘

  位置                    DEK 状态             可见性
  ────────────────────────────────────────────────────────
  开发者本地 (临时)       明文                 ✅ 开发者（用后擦除）
  HTTPS 传输 (登记时)     明文 (TLS 保护)      ✅ 仅本次请求
  KMXT 数据库            rootSecret 加密      ❌ 管理员看不到
  KMXT 管理后台          不返回               ❌ 前端看不到
  APK 文件               不存在               ❌ 逆向工程师拿不到
  租约响应 (HTTPS)       X25519+HKDF+GCM 封装 ❌ 中间人拿不到
  Android Java 层        不暴露               ❌ 反编译拿不到
  Android Native 层      内存明文 (handle)    ✅ 仅当前进程 5 分钟
  解密后                 擦除                 ❌ 内存取证拿不到


┌─────────────────────────────────────────────────────────────────────────────┐
│                         ⚠️ 常见误区                                          │
└─────────────────────────────────────────────────────────────────────────────┘

  ❌ 错误：「DEK 打包到 APK 的 BuildConfig」
     → 逆向工程师直接 jadx 反编译拿到明文 DEK
  
  ❌ 错误：「DEK 写入 SharedPreferences / 数据库」
     → Root 用户 / 备份泄露 DEK
  
  ❌ 错误：「管理员需要看到 DEK 方便调试」
     → 内部威胁 / 钓鱼攻击窃取 DEK
  
  ❌ 错误：「租约返回明文 DEK (JSON 字段)」
     → 中间人攻击 / 日志泄露 DEK
  
  ✅ 正确：「DEK 动态下发，用临时密钥封装，Native 解包，用后擦除」
     → 最小化攻击面，符合零信任原则


┌─────────────────────────────────────────────────────────────────────────────┐
│                         🎯 关键设计决策                                      │
└─────────────────────────────────────────────────────────────────────────────┘

  1. ✅ 为什么管理员看不到 DEK？
     → 防止内部威胁（账号被盗 / 社工攻击）
     → 管理员不需要知道 DEK（客户端自动获取）
  
  2. ✅ 为什么用临时密钥（X25519）？
     → 每次租约独立密钥，不可重放
     → 服务端不存储客户端长期密钥
  
  3. ✅ 为什么 handle 只有 5 分钟？
     → 减少内存攻击窗口
     → 强制客户端及时使用或重新请求
  
  4. ✅ 为什么不用对称密钥（AES）直接封装？
     → 需要客户端和服务端共享长期密钥（密钥分发问题）
     → X25519 临时密钥 = 完美前向保密
  
  5. ✅ 为什么不用 RSA？
     → X25519 更快（椭圆曲线 vs 大整数）
     → 更短的密钥长度（32 字节 vs 256 字节）


┌─────────────────────────────────────────────────────────────────────────────┐
│                         📊 性能指标                                          │
└─────────────────────────────────────────────────────────────────────────────┘

  操作                          耗时              备注
  ──────────────────────────────────────────────────────────
  客户端生成 X25519 密钥对      < 1ms             OpenSSL 硬件加速
  服务端解密 encryptedDek       < 0.5ms           AES-GCM + rootSecret
  服务端封装 DEK (X25519)       < 2ms             ECDH + HKDF + AES-GCM
  客户端解包 DEK (Native)       < 2ms             同上
  AES-GCM 解密 2.4 MiB 模型     < 10ms            ~240 MiB/s (Snapdragon 865)
  完整租约往返 (网络)           50-200ms          取决于网络延迟
  
  👉 端到端延迟：~60-220ms（网络主导），对推理启动影响可忽略
```

## 🔍 与传统方案对比

### 方案 A：DEK 写死在 APK（❌ 不安全）

```
APK 反编译 → BuildConfig.MODEL_DEK → 明文密钥 → 解密所有密文
攻击成本：10 分钟（jadx + 搜索 "DEK"）
```

### 方案 B：DEK 加密存在本地（⚠️ 风险）

```
Root 设备 → 读取 /data/data/.../dek.enc → 暴力破解 / 提取密钥
攻击成本：1-2 小时（Frida Hook / 内存 Dump）
```

### 方案 C：KMXT 动态下发（✅ 推荐）

```
逆向 APK → 只有密文 .vmp（无 DEK）
尝试网络抓包 → wrappedKey 是加密的（需要 X25519 私钥）
尝试 Hook Native → handle 有效期 5 分钟 + Ed25519 签名验证
尝试内存 Dump → DEK 用后立即擦除
攻击成本：数天到数周（需要绕过多层防护）
```
