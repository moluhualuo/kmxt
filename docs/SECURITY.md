# 安全设计

> 0.5.0 生产补充：MySQL 强制校验证书的 TLS；密码只从只读 secret 文件读取。生产 Nonce 使用 Redis `SET NX PX`，限流用原子 Lua。只有命中 `KMXT_TRUSTED_PROXY_CIDRS` 的直连代理才能提供 `X-Forwarded-For`。Android 会话由 Keystore AES-GCM 加密，并严格在线拒绝网络、TLS、解析、签名和到期失败。

## 保护目标

系统防止商户越权、数据库中直接泄露卡密和设备标识、伪造服务端授权响应、重复播放激活请求，以及禁用后继续使用现有会话。

它不能保证未受保护的客户端永远无法被修改。攻击者控制客户端机器时可以修改程序逻辑、跳过验证调用或截取进程内数据。客户端仍需要代码签名、完整性检查、混淆和关键业务服务端化等配套措施。

## 租户隔离

- 商户用户记录带有固定 `merchantId`。
- 路径中的商户或程序资源必须经过 `assertMerchantAccess`。
- 商户身份不从请求体读取。
- 卡密同时记录 `merchantId` 和 `appId`，激活时以 `appId + 卡密摘要` 查询。
- 程序签名密钥按应用独立生成，一个程序密钥泄露不会直接伪造其他程序响应。
- 自动化测试包含商户 A 访问商户 B 程序的拒绝场景。

## 机密存储

首次运行创建 32 字节根密钥 `data/secret.key`。根密钥通过用途标签派生子密钥：

| 数据 | 存储形式 |
| --- | --- |
| 管理密码 | 随机盐 scrypt 哈希。 |
| 卡密 | HMAC-SHA-256 摘要及遮罩预览。 |
| 管理令牌 | HMAC-SHA-256 摘要。 |
| 客户端会话 | HMAC-SHA-256 摘要。 |
| 设备 ID | 带 `appId` 用途标签的 HMAC-SHA-256 摘要。 |
| 程序私钥 | 根密钥派生密钥加密的 AES-256-GCM 密文。 |
| 订单联系方式 | 每个订单独立用途标签的 AES-256-GCM 密文及遮罩预览。 |
| 订单查询码 | HMAC-SHA-256 摘要。 |
| 订单交付卡密 | 每个订单独立用途标签的 AES-256-GCM 密文。 |

卡密明文只在批量创建响应中出现一次。日志、列表和数据文件均不返回明文。

修改本人密码必须校验当前密码。平台管理员可重置任一商户账号，商户管理员只能重置本商户其他账号；操作员无重置权限。密码变更与目标账号全部管理会话撤销位于同一存储事务，并记录审计日志。

`kmxt.json` 和 `secret.key` 必须分别限制文件权限，同时作为一组备份。丢失根密钥后无法继续验证已有卡密摘要，也无法解密程序签名私钥。

## 响应签名

每个程序创建一组 Ed25519 密钥。服务端对规范化后的 `payload` UTF-8 字节签名，并返回算法、`keyId`、载荷及 Base64URL 签名。客户端必须固定公钥，并按以下顺序处理：

1. 检查算法和固定 `keyId`。
2. 验证 Ed25519 签名。
3. 检查固定 `appId`。
4. 检查 `licensed === true`。
5. 检查授权和会话到期时间。

服务端错误响应没有授权效力。任何网络错误、HTTP 错误、无签名响应或验签失败都必须拒绝授权。

## 防重放与会话撤销

激活和心跳必须包含当前毫秒时间戳及随机 Nonce。单进程 ReplayGuard 在允许的时钟窗口内保存 Nonce，并拒绝重复值。客户端会话默认 30 分钟，通过心跳续期但不能超过卡密到期时间。

禁用商户、程序或卡密以及解绑设备，都会移除对应客户端会话。禁用商户还会撤销其管理会话。

当前 Nonce、速率限制状态位于进程内存，因此不能直接运行多个服务进程。多实例部署前必须使用 Redis 等共享原子存储实现这些状态。

## 公开订单

- 公开店铺只展示启用商户、启用程序和启用商品。
- 创建订单每个来源地址默认限制为每分钟 10 次，查询限制为每分钟 30 次。
- 查询订单必须同时持有不可预测的订单查询码；订单号本身不构成授权。
- 商品价格和授权参数在下单时写入快照，后续编辑商品不会改变已有订单。
- 人工发卡和订单状态更新在同一数据事务完成，并对重复请求保持幂等。
- 当前没有支付接口，服务不会把“已提交”视为“已付款”。商户应按自己的线下规则审核订单。

## HTTP 安全

- 请求体默认限制为 1 MiB。
- 管理接口要求 Bearer 会话。
- 登录、管理和客户端接口使用不同限流阈值。
- 响应设置 `nosniff`、禁止 framing、无缓存和不发送引用来源等安全头。
- CORS 默认关闭；只有设置 `KMXT_CORS_ORIGIN` 后才允许指定来源。
- 服务不会信任 `X-Forwarded-For`，反向代理场景的内置限流按代理地址聚合。公网部署建议由反向代理追加独立限流。

## 上线检查

- 更换强平台管理员密码并限制管理 API 来源。
- 使用 HTTPS，禁止明文公网访问。
- 限制 `data` 目录文件权限，不把根密钥提交到 Git。
- 配置进程监控、备份和日志告警。
- 迁移至事务数据库和共享 ReplayGuard 后再做多实例扩容。
- 对目标客户端执行签名、公钥固定和失败关闭测试。
- 定期检查异常登录、设备上限和高频激活记录。
