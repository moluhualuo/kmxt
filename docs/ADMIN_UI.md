# 管理后台

> 0.7.0：程序列表支持 Android 配置下载和加密模型制品入口；后台已接入 Dashboard、商户资料编辑、程序设置编辑、账号启停、卡密批次记录，以及订单和日志的筛选。下载接口仍执行登录角色与程序租户权限校验，绝不包含签名私钥。

## 0.7.0 后台接线

- 总览调用 `GET /api/v1/dashboard`，按当前商户和程序上下文显示订单、卡密、绑定及 24 小时验证统计；统计只包含已记录的 `activate/verify`，成功码为 `LICENSE_VALID`，主动解绑不计入失败。
- 商户页可仅修改名称；唯一代码只读。
- 程序页可修改名称、说明和授权/设备/心跳/离线宽限设置；程序代码和签名密钥保持只读。
- 加密模型制品页位于后台程序上下文；可通过侧栏“模型制品”沿用当前程序，也可点击程序列表每行的“模型”快捷按钮直接进入对应程序。页面按当前 `appId` 列出、批量选择明文文件、逐个上传加密、下载 `.vmp` 并切换制品状态，不接受跨商户的手工上下文参数。
- 账号页可重置密码、修改角色、启停非当前账号；停用确认会明确提示管理会话被撤销。
- 卡密页可查看批次元数据；平台管理员和商户管理员可显式查看单张完整卡密，操作会写入审计记录。
- 在线设备页按程序显示在线、离线和活动绑定统计，支持状态、设备名、卡密遮罩、版本及 IP 搜索，并可强制撤销设备会话。
- 订单页支持状态、订单号和时间范围；日志页支持动作或验证事件/结果及时间范围。

后台视图已拆分为 `public/js/views/overview.js`、`merchants.js`、`applications.js`、`model-artifacts.js`、`licenses.js`、`online-devices.js`、`products.js`、`orders.js`、`users.js` 和 `logs.js`。`views/shared.js` 提供一致的页面标题、权限判断、表格格式化和视图依赖；按钮、分页、对话框和转义组件继续位于 `public/js/components.js`。

管理后台由 Node.js 服务直接提供，入口为 `/admin/`。它使用原生 HTML、CSS 和模块化 JavaScript，不依赖 CDN 或前端构建工具。作者花落，项目代码使用 MIT 协议；Lucide 图标许可单独记录在 `public/assets/ATTRIBUTION.md`。

## 核心流程

### 创建授权业务

1. 平台管理员在“商户”创建商户并进入。
2. 在“账号”为商户创建管理员或操作员。
3. 在“程序”创建程序并设定默认天数、设备数、心跳及离线容忍。
4. 在“卡密”选择程序并生成批次。
5. 生成表单关闭后展示一次性结果，可复制或导出文本。

### 加密模型制品

1. 从侧栏”模型制品”进入时沿用当前程序；从”程序”列表某行的”模型”按钮进入时，先将该行程序设为当前上下文。页内程序选择器可继续切换 `appId`，但不提供脱离程序租户上下文的全局制品列表。
2. 上传对话框可一次选择多个明文模型文件，前端按文件逐个调用 `POST /api/v1/admin/artifacts/upload`。明文只通过受认证 HTTPS 进入 Node 内存；服务端为每个文件生成独立 DEK、加密并登记 draft，再把 `.vmp` 下载数据返回浏览器，不在服务端落盘。
3. 页面只提交版本、edition 和 keyVersion，不显示、导出或持久化 DEK。Nonce/tag 由服务端生成，后台上传固定使用整文件 AES-256-GCM；列表 API 可把 nonce/tag 作为非秘密加密元数据返回，但页面不渲染或导出，`contentKey` 和 `encryptedDek` 永不返回。大型模型应改用 `cli/publish-model-artifact.js` 在发布机本地加密，避免浏览器上传和 Base64 响应的内存开销。
4. 只有处于 `active` 的程序可以登记制品；新制品初始为 `draft`。页面显示总数及 draft/active/revoked 统计，可按三态筛选；表格展示名称、版本、edition、格式/加密算法、大小、密文摘要、对象 URL、状态和更新时间。拥有者在对象存储校验完成后切换为 `active`；客户端租约只能针对 `active` 制品。
5. 退回 `draft` 会停止新租约，但已签发租约仍有效至自身到期；切换为 `revoked` 则会同时将现有 `active` 租约标记为撤销。页面和后端都允许 `draft <-> active`，两种状态都可吊销；`revoked` 是不可恢复终态，重复吊销幂等，恢复请求返回 `409 ARTIFACT_REVOKED`。需要重新发布时应登记新制品。
6. `node cli/kmxt.js cleanup-sessions` 会删除已经到期的模型租约；未到期的 revoked 记录保留至自身 `expiresAt`。

### 公告与版本策略

1. 从侧栏”公告”进入或点击”程序”列表某行的”公告”按钮（扩音器图标）。页面按当前程序显示全部公告（包括草稿），按创建时间倒序排列。
2. 创建公告时需填写标题（2-200 字符）、正文（10-2000 字符，最多 20 行）、严重性（`info` 蓝色、`warning` 橙色、`critical` 红色）、展示位置，以及可选的时间窗口（`startsAt` 和 `endsAt`）。
3. **展示位置**决定这条公告出现在客户端的哪个页面，卡片上有对应的胶囊标记：
   - **全部页面**（`both`，缺省）：卡密验证页和软件内都显示
   - **仅验证页**（`gate`）：只在卡密验证页显示，用户激活进入软件后不再出现
   - **仅软件内**（`app`）：不出现在验证页，用户激活进入软件后才看到
   两条通道各自独立取最新 3 条，所以「仅验证页」的公告不会挤掉「仅软件内」的名额。历史公告没有这个字段，一律按「全部页面」处理。
4. 新创建的公告初始状态为 `draft`（草稿），不会下发到客户端。编辑公告可修改内容、展示位置和时间窗口，但不能修改序号。
5. 切换状态为 `published` 后，公告会按展示位置通过双通道下发：
   - **通道 A**（`both` / `app`）：已激活客户端在 `activate` 和 `verify` 响应中自动获得
   - **通道 B**（`both` / `gate`）：未激活客户端通过 `/api/v1/client/apps/:appId/notices` 获取
6. 服务端只下发 `status === 'published'`、在时间窗口内、且展示位置命中该通道的最新 3 条公告，按序号倒序排列。
7. 删除公告不会回退程序的 `announcementSequence` 计数器，新公告的序号会跳过被删除的序号（防止客户端防回滚机制误杀）。撤回发布或改成「仅软件内」同样不会让通道 B 的防回滚水位回落。
8. 在”程序”编辑对话框中设置版本策略（`minVersionCode` 最低版本要求、`latestVersionCode`/`latestVersionName`/`releaseNotes` 建议更新信息）。版本策略随公告一起下发，客户端低于 `minVersionCode` 时会禁用激活按钮。

**安全注意事项**：

- 公告内容使用纯文本，拒绝 `<>`、JavaScript URI 和控制字符（防止注入攻击）
- 只有 `platform_admin` 和 `merchant_admin` 可以创建/发布公告；`operator` 只读
- 每个公告经程序 Ed25519 私钥签名后下发，客户端必须验证签名和 `appId`
- 公告序号单调递增，客户端持久化已见最大序号并拒绝回滚（防降级攻击）

### 卡密和设备

卡密页面支持程序切换、状态筛选、完整卡密精确查询和分页。启停卡密会弹出风险确认。平台管理员和商户管理员可在二次确认后查看完整卡密或删除未关联订单的卡密；查看与删除均会写入审计记录。删除会撤销全部客户端会话、清除设备绑定和验证记录。设备按钮显示绑定历史；可单独解绑活动设备，也可在存在活动绑定时使用“解绑全部设备”。批量解绑会立即撤销该卡密的全部客户端会话、保留绑定历史并写入一条卡密级审计记录。

### 在线设备

“在线设备”是独立侧栏页面，默认仅显示在线设备。页面顶部统计当前程序的在线、离线、活动绑定和在线判定窗口；表格显示设备标签、卡密遮罩、客户端版本、可信来源 IP、最后在线和会话到期时间。程序、状态、每页数量和搜索条件变化都会回到第一页。

在线状态不是仅凭绑定判断：活动绑定必须存在未到期会话，且最后心跳位于 `heartbeatSeconds × 2`（最低 60 秒）的窗口内。强制下线会二次确认并调用 `POST /api/v1/device-bindings/:bindingId/disconnect`，只撤销会话、不解绑设备；设备重新激活时复用原绑定，不额外消耗设备名额。

### 日志

“日志”使用分段控件切换管理审计与程序验证记录。操作员只能看到程序验证记录。所有列表按当前商户或程序范围查询。

### 商品和订单

“商品”按当前程序配置店铺套餐，包括展示价格、授权天数、设备上限、排序和启停状态。设备上限填 `0` 表示无设备绑定上限，默认仍为 1 台。“打开店铺”在新标签页进入当前商户的公开页面。

“订单”按商户分页和筛选，并使用订单专属状态文字区分“待处理、已发卡、已拒绝”。待处理订单可以发卡或拒绝；发卡会自动创建一张对应程序卡密，重复提交不会重复生成。已发卡订单可复制卡密，客户同时可以在公开店铺凭查询码领取。

## 会话与安全

- 管理令牌保存在 `sessionStorage`，关闭标签页后清除，不写入 URL。
- 所有 API 数据在插入 HTML 前通过 `escapeHtml` 转义。
- `401` 响应会清除本地会话并返回登录页。
- 修改本人密码成功后主动返回登录页；管理员重置密码后目标账号必须重新登录。
- 静态资源使用 CSP，仅允许同源脚本、样式、图片和 API 请求。
- 卡密列表与批次记录不显示明文；仅平台管理员或商户管理员在二次确认后可按单张卡密显式查看，且每次查看均留有审计记录。
- 模型制品列表不显示 `contentKey`、`encryptedDek` 或租约包裹密钥；nonce/tag 即使作为非秘密加密元数据返回，也不在表格中渲染或导出。页面只展示制品身份、版本、格式、状态、大小、摘要和对象 URL 等安全元数据。
- 管理后台不能替代 HTTPS；公网部署必须由反向代理终止 TLS。

## 响应式与无障碍

- 桌面使用 244px 固定侧栏和数据表布局。
- 侧栏账号名称与密码、退出操作分行布局，长名称保持可读且不挤压图标按钮。
- 桌面隐藏移动菜单按钮；820px 以下侧栏变为可关闭抽屉，窄屏顶部栏隐藏重复标题并为商户选择器保留固定空间。
- 登录页在 820px 以下切换为受 `100vw` 限制的单列布局；表单使用零最小宽度约束，表格只在自身容器内横向滚动，不扩张页面。
- 所有主要按钮至少 40px，高频图标按钮为 42px；移动导航操作区域不小于 44px。
- 表单输入均有显式标签；图标按钮具有 `aria-label` 和悬停标题。
- 键盘焦点使用高对比描边，对话框使用浏览器原生焦点管理。
- 支持 `prefers-reduced-motion`，减少动画用户不会看到持续过渡。
- 状态同时使用文字和颜色，不以颜色作为唯一信息。

## 运行态验收

Windows 环境可使用本机 Chrome 或 Edge 执行真实浏览器验收：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/ui-smoke.ps1 `
  -Username admin -Password "管理员密码" `
  -Width 375 -Height 812 -Screenshot .runtime/mobile.png
```

公开店铺无需登录：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/ui-smoke.ps1 `
  -Public -Path /store/MERCHANT_A `
  -Width 375 -Height 812 -Screenshot .runtime/store-mobile.png
```

公开店铺的已发卡查询状态可附加 `-StoreOrderNo` 和 `-StoreQueryCode`；两个参数必须同时提供，脚本会提交真实查询表单并等待卡密交付或拒绝结果。

脚本通过 DevTools 设备指标创建精确 CSS 视口，可提交真实后台登录表单或等待公开店铺加载，检查文档宽度是否超过视口，并保存 PNG 截图；后台截图后主动退出本次管理会话，随后关闭测试浏览器并删除临时配置。标准输出仅返回验收 JSON，密码只用于当前测试进程且不写入文件。


## 2026-07-17 卡密批量删除与分页显示

作者：花落；协议：MIT。卡密列表支持勾选当前页卡密后批量删除，按钮在未选择时禁用，执行前二次确认。批量删除调用 `POST /api/v1/apps/:appId/licenses/bulk-delete`，后端对每个卡密逐个执行订单保护、租户隔离、会话撤销、设备绑定清理和审计写入；已关联订单的卡密不会被删除，并在结果中显示为失败项。

卡密列表新增每页显示数量选择，支持 20、50、100。前端切换每页数量时会回到第一页并清空已选项；后端 `parsePagination` 继续强制 `limit <= 100`，避免一次请求加载过多数据。
