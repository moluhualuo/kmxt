# 用户店铺

用户店铺为每个商户提供独立入口：

```text
/store/:merchantCode
```

例如商户代码为 `MERCHANT_A`，地址为 `http://127.0.0.1:8080/store/MERCHANT_A`。当前版本不接入支付，使用“提交订单 -> 商户人工审核 -> 自动生成卡密 -> 用户查询领取”的流程。

## 商户配置

1. 登录管理后台并选择商户和程序。
2. 打开“商品”，创建套餐。
3. 配置商品名称、说明、展示价格、授权天数、设备上限和排序；设备上限为 `0` 时公开店铺显示“无限制设备”。
4. 启用商品并点击“打开店铺”检查用户页面。
5. 用户下单后，在“订单”页面发卡或拒绝。

展示价格只作为人工审核参考，系统不会收款，也不会自动判断付款状态。价格使用整数分存储，避免浮点金额误差。

## 用户流程

1. 用户打开商户店铺并选择套餐。
2. 填写联系方式，可选填写称呼和备注。
3. 提交后取得订单号和高熵查询码。
4. 商户审核订单并发卡。
5. 用户在“订单查询”输入两个凭证领取卡密。

浏览器会尝试把最近 10 个订单的订单号和查询码保存在当前域名的 `localStorage`，用于本机快捷查询。若浏览器禁止本地存储，订单仍会成功创建，页面会明确提示立即复制凭证。用户仍应保存首次提交页面显示的凭证；清除浏览器数据或更换设备后，本机记录无法恢复。

“选择套餐”和“订单查询”使用 URL Hash 保存当前视图，浏览器前进和后退操作会同步切换页面。

## 订单状态

| 状态 | 用户显示 | 商户操作 |
| --- | --- | --- |
| `pending` | 等待商户处理 | 发卡或拒绝。 |
| `fulfilled` | 显示可复制卡密 | 不能再次生成新卡，重复发卡返回原结果。 |
| `rejected` | 显示拒绝原因 | 不能再发卡。 |

移动端卡密保持单行并仅在卡密代码区域内部滚动，便于核对分组；页面本身不会产生横向滚动。

## 数据保护

- 联系方式使用 AES-256-GCM 加密，列表仅向有权访问该商户的管理账号解密。
- 订单查询码只保存 HMAC 摘要，服务无法从数据文件还原原查询码。
- 为支持用户以后领取，订单卡密使用订单专属派生密钥加密；普通卡密表仍只保存摘要。
- 公开 API 只返回订单号、商品快照、遮罩联系方式、状态和交付结果，不暴露内部商户、程序、商品、卡密或绑定 ID；错误响应不区分订单号存在与否。
- 查询码等同订单领取凭证，不应发布到聊天群、日志或 URL。

## 后续支付接入

未来接入支付时，应在 `pending` 与 `fulfilled` 之间增加支付状态，并由经过签名验证且幂等的支付回调触发发卡。不能根据浏览器跳转结果直接发卡。
